# 第一问已知天气单玩家最优策略：实现与报告设计

## 1. 目标与范围

本项目完成 2020 年数学建模竞赛 B 题第一问的第一关、第二关求解。天气在 30 天内全部已知，要求在题设预算、负重、资源消耗、沙暴禁行、村庄补给、矿山收益和截止日期约束下，使到达终点后的总财富最大。

本轮范围包括：数据结构化、地图预处理、精确求解、逐日策略输出、独立规则检验、剪枝正确性验证、灵敏性分析，以及供论文写作参考的 DOCX 求解报告。不包括可视化绘图代码和图像输出。

## 2. 输入口径

- 两关公共参数：负重上限 1200 kg、初始资金 10000 元、截止日第 30 天、矿山基础收益 1000 元/天。
- 水：3 kg/箱、基准价 5 元/箱；食物：2 kg/箱、基准价 10 元/箱。
- 晴朗、高温、沙暴的基础消耗分别为：水 5/8/10 箱，食物 7/6/10 箱。
- 停留、行走、挖矿的消耗倍率分别为 1、2、3；沙暴日禁止行走，但允许在矿山挖矿。
- 第一关：27 节点用户核对邻接表；起点 1，村庄 15，矿山 12，终点 27。
- 第二关：8×8 错位六邻域网格，共 64 节点；起点 1，村庄 39、62，矿山 30、55，终点 64。
- 第 0 天在起点按基准价采购一次；村庄按 2 倍基准价补给；到终点后剩余资源按基准价一半回收。
- 状态统一采用“第 t 天结束且已扣除当日消耗、已完成当日村庄采购”的日末口径。

## 3. 求解方法选择

主方案采用完整原图上的有限期稀疏标签动态规划。阶段为日期，状态索引为 `(t, node, water, food)`，现金作为该状态的最大价值而不作为额外维度。每个状态枚举停留、合法移动、矿山挖矿和日末村庄补给，并保存前驱以回溯完整策略。

采用三类不改变最优解的压缩：同日同节点 Pareto 支配、考虑未来沙暴的最早到达时间剪枝、基于剩余最大挖矿收益的乐观上界剪枝。功能节点压缩和 MILP 不作为主求解器，以避免额外等价性假设或重型求解依赖。

## 4. 模块设计

`求解代码/第一问/模型求解/config.py` 保存公共参数、天气和两关地图配置；`preprocess.py` 建图、计算 BFS 距离并执行输入断言；`solver.py` 实现稀疏标签 DP、支配与可达性剪枝；`checker.py` 从输出策略独立重放全部规则；`run.py` 统一求解两关并生成结果。

`求解代码/第一问/tests/` 使用 pytest 覆盖天气消耗、动作合法性、初始采购、村庄采购、矿山收益、终点结算、支配关系、地图构造及小型实例最优值。实现遵循测试先行的红—绿—重构循环。

`求解代码/第一问/结果输出/` 保存两关逐日 CSV、求解摘要 JSON 和填写完成的 `Result_已填写.xlsx`。公共 `数据/Result.xlsx` 只作为模板和输入，不原地覆盖。

## 5. 目标函数与核心约束

终端目标为：

`max Z = C_tau + 0.5 p_w W_tau + 0.5 p_f F_tau`，其中 `tau <= T` 且终点状态到达后停止扩展。

每日资源递推为：

`W_t = W_{t-1} + b^w_t - kappa(a_t)c_w(omega_t)`，

`F_t = F_{t-1} + b^f_t - kappa(a_t)c_f(omega_t)`。

现金递推为：

`C_t = C_{t-1} + R I(a_t=Mine) - 2p_w b^w_t - 2p_f b^f_t`。

所有水、食物和采购量均为非负整数；现金与库存不得为负；`3W_t+2F_t <= 1200`；移动必须沿邻接边且沙暴日不可移动；挖矿仅能在当日开始时已经位于矿山时发生；采购仅允许第 0 天起点或日末村庄。

## 6. 验证设计

1. 输入校验：天气长度和取值、邻接对称性、无自环、节点范围、起终点连通性、功能节点合法性。
2. 单元测试：逐项验证规则引擎和剪枝的边界条件。
3. 独立逐日重放：不读取 DP 内部累计值，仅依据动作、采购和天气重新计算库存、资金、负重和终端财富。
4. 精确性对照：在缩小地图和缩小资源上比较剪枝版与无剪枝穷举/DP的最优值与策略可行性。
5. 结果一致性：CSV、JSON、Excel 和 DOCX 中的关键结果必须来自同一份机器生成摘要。
6. 灵敏性分析：对负重上限、初始资金、矿山收益和截止日期做离散扰动，记录最优财富、到达日、挖矿天数和策略结构变化。该分析重新求解模型，不使用与本题不相干的残差正态性或回归显著性检验。

## 7. DOCX 求解报告设计

最终报告保存为 `求解报告/第一问求解报告.docx`，作为论文第一问写作参考，采用正式数学建模报告体例。

报告包含：

1. 问题重述：用原创语言说明资源受限路径决策的现实背景、核心目标和硬约束；提炼地图数据化、统一优化、可靠性验证三个子任务；引用近 3—5 年资源约束路径与补给路径领域的代表性研究，但不把论文数值作为模型输入。
2. 问题分析：采用总—分结构，分别以“问题1分析”“问题2分析”“问题3分析”组织三个子任务，说明关键矛盾、思路框架、步骤衔接和文字版流程图，不提前写入求解结果。
3. 模型假设：给出 3—5 条直接相关假设，每条同时说明假设内容、合理性依据和模型影响。
4. 符号说明：以三线表列出图、节点集合、时间、天气、库存、现金、采购、状态价值、终端财富和上界等全局符号、含义与单位。
5. 模型建立：说明图预处理、状态定义、决策变量、目标函数、初始条件、动作约束、库存与现金递推、村庄补给、终点结算、Bellman 方程、Pareto 支配和安全剪枝，并给出推导逻辑。
6. 模型求解：说明 Python 实现、初始化、逐日扩展、前沿维护、终点更新、回溯和输出过程；分别报告第一关和第二关的机器求解结果与逐日策略要点。
7. 结果分析与建议：解释路线、挖矿、补给、等待与天气之间的关系，分析最终财富构成和约束紧张程度，不虚构图表或拟合指标。
8. 模型检验与灵敏性分析：报告输入检查、单元测试、独立规则重放、剪枝一致性和参数扰动的实际结果，并明确检验范围。

文档正文需详细但避免重复和空泛模板语句。公式使用可读数学形式，表格保持三线表风格。完成后进行结构审计；若 LibreOffice 仍不可用，则使用本机 Word 导出或在最终说明中如实披露无法完成分页渲染 QA。
