## 一、修改背景

### 1.1 三份权威文档之间的冲突

重构前，第一问的代码实现与《手册》之间存在系统性偏离，且这种偏离在重构前 **未在文档层面被识别**：

| 权威来源 | 规定的主模型 | 重构前的实际代码 | 一致性 |
|---|---|---|---|
| 《手册》§0（推荐架构） | **稀疏标签动态规划（DP）** | HiGHS 整数线性规划 | ❌ 算法不同 |
| 《手册》§2.3 | "MILP **不作为主模型**，仅作为可选独立校验" | MILP 作为唯一生产求解器 | ❌ 角色颠倒 |
| 《手册》§5.2–5.4 | Pareto / 时间可达 / 收益上界三种剪枝必须存在 | 三种剪枝均未实现 | ❌ 缺失 |
| 《手册》§6.3 伪代码 | `labels[t] = pareto_prune(next)` | 无 `labels` 字典、无 `pareto_prune` | ❌ 无对应结构 |
| 第一问求解流程图 | "Pareto 匹配 + 最早到达日 + 收益上界剪枝 → 删除不可行状态" | 由 MILP 约束自然满足 | 含义对、机制错 |
| 《第一问求解报告》§5.9 | "等价整数网络流展开" → HiGHS MILP | HiGHS MILP | ✅ |

可以看到：《手册》和流程图明确要求"DP 主模型 + 三种剪枝"；《求解报告》则把 DP 视作理论基础，把 MILP 作为工程实现。**两份设计文档之间本身就存在不一致**，而代码过去对齐到的是《求解报告》，导致《手册》长期未被实现。

## 三、`dp.py`——按《手册》§5 实现的稀疏标签 DP

### 3.1 状态与值函数

完全对齐《手册》§5.1.2 公式（5.2）：

$$
S_t = (t, i_t, W_t, F_t),\quad V_t(i, w, f) = \text{该状态可达到的最大现金}
$$

实现层结构：

```python
@dataclass(frozen=True)
class _Label:
    cash: int                                    # V_t(i, w, f)
    prev: tuple | None                           # 前驱指针 (t', i', w', f', action, bw, bf)
```

`labels[t][i]` 是 `dict[(w, f) → _Label]`，即 §6.3 伪代码中的"稀疏标签字典"。每条标签只在它能由合法动作产生时出现，**现金维度不进入状态索引**，而由价值函数保存，符合 §5.1.2 第二句"现金不显式加入 DP 索引"。

### 3.2 三种精确剪枝

#### 3.2.1 Pareto 支配剪枝（§5.2）

定义 A ≽ B（与《手册》一字不差）：

$$
A \succcurlyeq B \iff w_A \ge w_B \wedge f_A \ge f_B \wedge C_A \ge C_B \wedge (\text{至少一项严格})
$$

实现策略：按 `w` 降序扫描，维护已保留点中 `(f, cash)` 的二维 Pareto 前沿；新点插入时先做支配查询，再清理被新点支配的旧前沿项。

```python
def _pareto_prune(labels):
    items = sorted(best.items(), key=lambda kv: (-kv[0][0], -kv[1].cash, kv[0][1]))
    for key, label in items:
        # 支配查询：front 中是否有点 (f', c') 使 f' ≥ f ∧ c' ≥ cash ∧ 至少一项严格
        # 若被支配，跳过；否则清理被支配项后加入 front 与 kept
```

#### 3.2.2 时间可达性剪枝（§5.3）

考虑未来沙暴日的"最早到达日"下界，比"剩余天数 ≥ 最短步数"更强：

```python
def _earliest_arrival(t, dist, deadline, weather):
    """从第 t 天末出发到目标的理论最早日期；返回 None 表示截止日前不可达。"""
    if dist == 0:
        return t
    needed = dist
    for q in range(t + 1, deadline + 1):
        if weather[q - 1] != "沙暴":
            needed -= 1
            if needed == 0:
                return q
    return None
```

预计算 `earliest[t][node]` 表后，主循环每个状态都用它做"是否可被剪枝"的 O(1) 查询。

#### 3.2.3 乐观收益上界剪枝（§5.4）

UB 公式与《手册》§5.4 完全一致：

$$
\mathrm{UB} = C + 0.5\,p_w W + 0.5\,p_f F + (T - t)\,R
$$

若 `UB ≤ best_terminal`，该状态绝无可能改善最优解，安全剪枝。该剪枝只在已有可行终态后才启用（`best_terminal == -∞` 时跳过），避免在搜索初期误剪。

**重要发现**：由于 `cash = C₀ − 5w − 10f` 严格线性于 `(w, f)`，初始层所有可行点互不支配（数学上证明见 §六），所以初始 Pareto 剪枝**在数学上不削减规模**。代码用 `if len(labels_at_start) <= 2000: _pareto_prune(...)` 避免在大型初始层跑 O(n²) 调用。

### 3.4 每日动作枚举（§5.1.5）

```python
def _legal_actions(level, weather_today, from_node):
    actions = []
    if from_node == level.goal:
        return []
    if weather_today != "沙暴":          # §5.1.5 沙暴禁行走
        for neighbor in level.neighbors[from_node]:
            actions.append((neighbor, "行走"))
    if from_node in level.mines:           # §5.1.5 挖矿需在矿山
        actions.append((from_node, "挖矿"))
    actions.append((from_node, "停留"))    # 总是允许停留
    return actions
```


### 3.6 终点吸收与终端财富（§5.1.3 / §5.1.9）

到达 `level.goal` 后立即停止该路径的后续扩展，并计入 §5.1.3 的终端价值：

$$
Z = C_\tau + 0.5\,p_w W_\tau + 0.5\,p_f F_\tau,\quad i_\tau = g,\; \tau \le T
$$

代码层把"半价回收 + 到达即停"显式写为：

```python
if to_node == level.goal:
    z = cash_mid + 0.5 * p_w * w_mid + 0.5 * p_f * f_mid
    if z > best_terminal:
        best_terminal = z
        best_terminal_label = (t + 1, to_node, w_mid, f_mid, cash_mid)
        # 同时把终态存入 labels[t+1][goal] 以便回溯
        next_layer[to_node][(w_mid, f_mid)] = _Label(...)
    continue   # §5.1.9：到达后不再扩展
```

> 《手册》§7.1 "模型检验"明确把"到达后继续挖矿"列为必查陷阱。该测试 (`test_solver_cannot_leave_goal_to_reach_mine`) 已通过。

### 3.7 前驱回溯

`_Label.prev` 字段记录 `(prev_t, prev_i, prev_w, prev_f, action, bw, bf)`。`_backtrack` 从最优终态逆推 `t` 步，得到逐日 `DailyRecord`，**并返回起点实际使用的 (w, f)**，避免初始采购被一个无依据的"最大回收值"贪心误选。

> **Bug 修复记录**：重构前 `_enparse_initial` 用 `max(初始层 by 回收值)` 选初始采购，会选出 `(40, 0)` 这类根本无法走路到达终点的状态。`_backtrack` 直接从终态反查起点状态是正确做法，详见 §六.1。

### 3.8 主循环结构

对应《手册》§6.3 伪代码：

```text
for t = 1..T:
    next = empty sparse label sets
    for each node i and label in labels[t-1]:
            if 不可达: continue  advance                                 # §5.3
            for a in 合法动作:
                    扣除消耗 + 挖矿现金更新
                    if to == goal:  # §5.1.3 / §5.1.9
                            更新 best_terminal 与 best_terminal_label
                            continue
                    if UB ≤ best: continue                               # §5.4
                    村庄补给闭包（§5.1.8）→ 候选集
                    取同 (w, f) 的最大现金者插入 next[j]                  # DP 同点合并
    labels[t] = pareto_prune(next)                                       # §5.2
backtrack(best_terminal)
```

## 四、`milp.py`——从 `solver.py` 独立出来的 MILP

### 4.1 拆分动机

重构前 `solver.py` 同时承担两件事：(1) MILP 模型的构造与求解；(2) 与外部代码的 API 接口。重构后：

- `milp.py`：纯 MILP 求解器，不依赖任何外部状态；
- `solver.py`：薄壳层，负责选项解析和结果包装；
- `dp.py`：纯 DP 求解器，与 `milp.py` 平级。

这样切分后，DP 与 MILP 可独立测试、独立替换、独立交叉验证（见 §5.3）。

### 4.2 MILP 等价性依据

MILP 模型与 DP 在数学上等价（不是近似）：

| DP 元素 | MILP 元素 |
|---|---|
| 状态 `V_t(i, w, f)` | 整数变量 `cash[t]`（约束为 ≤ max） |
| 状态可达 `x[t, i] ∈ {0, 1}` | 0-1 变量 `x[t, i]` |
| 动作选择 | 0-1 变量 `move[t, i, j]`、`stay[t, i]`、`mine[t, i]`、`finish[t]` |
| 资源递推（公式 9-12） | 线性等式 |
| 沙暴禁行 / 终点吸收 | 边界约束 / 大 M 约束 |
| Bellman max | 线性目标 `max Σ(−2·cash[t] − pw·water[t] − pf·food[t])` |

HiGHS 在 mip_rel_gap=0 下给出分支定界的全局最优。**所有用 MILP 求出的解，都满足 DP 的所有约束，反之亦然**——所以重构前重构后的所有数值结果都完全一致（见 §七）。

## 六、重构中遇到的核心问题

### 6.1 起点采购选择器 bug（已修复）

**症状**：单测 `test_solver_finds_direct_two_day_optimum` 期望 `final_wealth == 9620`，但重构前 DP 给出 `8717.5`。

**根因**：旧实现中，初始层 `_enparse_initial` 返回所有可行 `(w, f)` 后，用以下启发式选"代表性"采购：

```python
initial_purchase = max(
    labels_at_start.keys(),
    key=lambda k: labels_at_start[k].cash + 0.5 * p_w * k[0] + 0.5 * p_f * k[1],
)
```

这一行在 DP 还没跑时就贪心地选出"半价回收值最高"的 `(w, f)`，对本题会选出 `(40, 0)`（高 w，无 f）。但 `(40, 0)` 的 f=0 < 行走日消耗 14，根本走不到终点。

**修复**：删掉启发式选择，让 `_backtrack` 从最优终态逆推 prev 链，自然得到真正的 `(w_init, f_init)`。修复后最优值变为 `9620`，初始采购变为 `(20, 28)`——与《手册》§7.5 灵敏性分析所引用的 9620 元基准一致。

### 6.2 初始层 Pareto 剪枝无效（已记录于代码注释）

《手册》§5.2 把 Pareto 列为"必要改进"。但在本题中：

> 由于 `cash = C₀ − 5w − 10f` 严格线性于 `(w, f)`，初始层所有可行点互不支配。

**严格证明**（已写入 `dp.py` 第 145-148 行的注释）：设 A = (w_A, f_A, C₀ − 5w_A − 10f_A)，B = (w_B, f_B, C₀ − 5w_B − 10f_B)。若 A ≽ B，则要求

$$
w_A \ge w_B,\; f_A \ge f_B,\; 5w_A + 10f_A \le 5w_B + 10f_B
$$

但前三项蕴含 `5w_A + 10f_A ≥ 5w_B + 10f_B`，等号仅当 `(w_A, f_A) = (w_B, f_B)`。所以严格 Pareto 支配关系**不存在**，初始层 Pareto 边界退化为全部 120,601 个可行点。

代码层应对：

- `_enparse_initial` 在规模 > 2000 时跳过 Pareto 调用；
- 主循环在批次规模 > `pareto_threshold`（默认 10000）时跳过 Pareto 调用。

这与《手册》§5.2 的表述并不矛盾——§5.2 描述的是"通用"剪枝机理，本题的初始段恰好不触发该剪枝的削减效果。§5.2 在"村庄补给后 + 挖矿后"等现金不再纯线性的阶段仍然有效。

### 6.3 "每维取最大"枚举误删内部 Pareto 点（已修正）

第一版实现尝试用"每维贪心"枚举：

```python
for w in range(max_water):
    f_max = min(budget_max, weight_max)
    candidates[(w, f_max)] = ...    # ← 只取 f 最大者
for f in range(max_food):
    w_max = min(budget_max, weight_max)
    candidates[(w_max, f)] = ...
```

这只生成 Pareto 边界的**顶 / 右端点**，遗漏了 (20, 28) 这类内部 Pareto 点。

**修正**：改为完整双层枚举 `O(W_max × F_max)`，再用 Pareto 筛选。初始枚举 0.10 s 即可完成 120,601 个状态。

### 6.4 终点状态未存入 `next_layer` 导致回溯失败（已修复）

第一版在到达终点时只更新 `best_terminal_label`，未把标签存入 `labels[t+1][goal]`。`_backtrack` 在终态查找时报 `KeyError: (0, 0)`。

**修正**：到达终点时同步写入 `next_layer[goal][(w_mid, f_mid)] = _Label(cash_mid, prev=...)`，使 prev 链可回溯到 `t=0`。

### 6.5 DP 在完整规模下的纯 Python 性能瓶颈（已知限制）

实测数据（`DPOptions(pareto_threshold=0, disp=True)`）：

| 日 t | 当日总标签数 |
|---|---|
| 0 | 120,601 |
| 1 | 326,685 |
| 2 | 680,263 |
| 3 | 902,045 |
| 4 | 817,472 |
| 5 | 977,413 |
| 6 | 1,129,475 |
| 7 | 1,006,746 |
| ... | （持续累计，直到截止日） |

主循环迭代数 ≈ ∑_t (当日总标签 × 动作数 × 出边数)。30 天 × 27 节点的理论下界即 ≥ 4 × 10^8 次状态-动作转移。**纯 Python 实测**：

- Level 1（27 节点）：10 分钟内未完成；
- Level 2（64 节点）：更慢。

**根因**：本题 cash 与资源严格线性相关，Pareto 剪枝在初始与前期不削减状态，必须遍历全部可行 (w, f) 组合。MILP 把整个 30 天一次性展平为整数线性模型，由 HiGHS 的 C++ 内核求解，规避 Python 解释器开销。

**应对策略**：

1. 默认走 MILP（`use_dp=False`）；
2. DP 仍完整实现并被 16 个单元测试与 4 个端到端求解测试覆盖，可通过 `SolveOptions(use_dp=True)` 启用；
3. 未来加速路径（未实施）：numpy 向量化、用 Cython / numba 重写内层循环、利用"先跑 MILP 取最优初始采购 (w*, f*)，再以 (w*, f*) 为 DP 起点验证"。

## 十、与《第一问求解报告》§5.9 的关系
