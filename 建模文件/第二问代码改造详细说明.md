### 2.1 [`pareto_utils.py`](求解代码/第二问/模型求解/pareto_utils.py)（新增，118 行）

**改动内容**：

```python
def pareto_prune_3d(labels, threshold=10_000) -> dict
def optimistic_upper_bound_3d(water, food, cash, deadline, current_day,
                              water_price, food_price, mine_income) -> float
def optimistic_upper_bound_4d(... storm_budget, storm_factor=1.0) -> float
```

**具体实现要点**：

- **`pareto_prune_3d`**：输入 `{(w, f, cash): score}` 字典。算法严格沿用 [求解代码/第一问/模型求解/dp.py:92-135](求解代码/第一问/模型求解/dp.py#L92-L135)：
  1. 同 `(w, f, cash)` 键仅保留最大 score；
  2. 按 `w` 降序、`score` 降序、`f` 升序排列；
  3. 扫一遍时维护 (f, score) 上的 2D frontier；
  4. 桶规模 > `threshold` 时**直接跳过**（与 dp.py:445 一致），O(n²) 在 frontier ≤200 时仍可控。

- **`optimistic_upper_bound_3d`**：严格沿用 [dp.py:222-247](求解代码/第一问/模型求解/dp.py#L222-L247) 公式：
  ```
  UB = cash + 0.5 × p_w × W + 0.5 × p_f × F + (T - t) × R
  ```
  三个乐观假设：（1）剩余资源可按 half 价回收；（2）未来每天都能挖矿；（3）未来不购买。

- **`optimistic_upper_bound_4d`**：在 3D 基础上叠加剩余沙暴预算可能带来的等待日挖矿收益（用于 `AdaptiveBudgetRobustSolver` 内可选分支）。

**改动原因**：

1. **代码复用**：第三关的 `AdaptiveRobustSolver`、第四关的 `AdaptiveBudgetRobustSolver`、`oracle_dp` 均需要 Pareto 剪枝与乐观上界，三处实现共享同一份代码以避免漂移。
2. **与第一问一致**：把第一问验证过的剪枝参数（`threshold=10000`、O(n²) 复杂度）原样搬入，确保建模语义不漂移。

### 2.2 [`nominal_mdp.py`](求解代码/第二问/模型求解/nominal_mdp.py)（新增，265 行）

**改动内容**：

```python
@dataclass(frozen=True)
class NominalDecision:
    action: Action | None
    expected_value: float

@dataclass(frozen=True)
class NominalMDPResult: ...

class NominalMDPSolver:
    def __init__(self, level, game, weather_states=("晴朗","高温","沙暴"))
    @lru_cache(maxsize=None)
    def _value(self, day, node, water, food, cash, current_weather) -> NominalDecision
    def decide(self, day, state, current_weather) -> NominalDecision
    def simulate(self, state, weather_sequence) -> SimulationResult

def solve_nominal_mdp(level, game, weather_states, ...) -> NominalMDPResult
```

**具体实现要点**：

- **状态键**：`(t, node, water, food, cash, current_weather)`，**无 storm_budget 维度**（与 `AdaptiveBudgetRobustSolver` 不同）。
- **Bellman**（建模手册 §7）：
  ```
  V̄(t, s, ω) = max_a Σ_{ω' ∈ W} P̂_{ω,ω'} · V̄(t+1, T(s, a, ω), ω')
  ```
  决策只依赖当前观测 ω；未来天气分布由 P̂ 直接编码。
- **时间下界**：`dist_to_goal[node] ≤ deadline - day + 1`（无沙暴预算维度简化版）。
- **完整初始采购搜索**：`solve_nominal_mdp` 枚举 `max_water × max_food`（容量约束下）所有候选，求使期望财富最大的 `(water, food)`。
- **`simulate` 与 `AdaptiveRobustSolver` 同形态**：返回 `SimulationResult`，可直接用于 Monte Carlo 评估。

**改动原因**：

1. **补齐手册 §8.5 基线对比**：原代码仅有 3 类策略（鲁棒 / Q1 固定 / 低保护），缺少"风险中性名义策略"作为对照。
2. **独立模块**：名义 MDP 与鲁棒 DP 解题思路不同（max 期望 vs max-min 最坏），分开实现便于论文 §7 与 §8.5 单独讨论。

### 3.1 [`robust_dp_q4.py`](求解代码/第二问/模型求解/robust_dp_q4.py)（+514 行净增：原 ~210 行 → 724 行）

#### (a) 新增完整鲁棒 DP（手册 §6.2 + §6.4）

```python
NEG_INF = float("-inf")

@dataclass(frozen=True)
class Decision:  # 与 AdaptiveRobustSolver.Decision 同形态
    action: Action | None
    robust_value: float
    nominal_value: float
    prev: tuple | None

@dataclass(frozen=True)
class AdaptiveBudgetRobustResult:
    optimal: bool
    status: str
    final_wealth: float

    """第四关完整自适应鲁棒 DP（手册 §6.2 + §6.4）"""
    def __init__(self, level, game, gamma)
    def _next_weather_states(self, b)         # 沙暴预算下未来天气集合
    def _next_weight(self, cur_ω, next_ω, b)  # 条件化 Markov 权重
    def _time_feasible(self, day, node, storm_budget)  # 时间下界
    def _revenue_ub(self, water, food, cash, day)       # 乐观收益上界
    @lru_cache(maxsize=None)
    def _value(self, day, node, water, food, cash, current_weather, storm_budget) -> Decision
    def _legal_actions_q4(self, state, weather) -> list[Action]
    def decide(self, day, state, current_weather, storm_budget=0) -> Decision
    def simulate(self, state, weather_sequence, storm_budget=0) -> SimulationResult

def solve_initial_purchase_q4(level, game, gamma, ...) -> AdaptiveBudgetRobustResult
```

**算法骨架**（严格沿用第一问 [dp.py:339-490](求解代码/第一问/模型求解/dp.py#L339-L490) 标签数组，但**加入沙暴预算维度**）：

1. 状态键 `(t, node, water, food, cash, storm_budget)`，budget 含今日——若 `b=0` 且 `ω=沙暴` 状态非法，立即返回 NEG_INF（一致性检查）。
2. **三类剪枝**：
   - **时间下界**：`moves_possible = (deadline - day - future_budget) + today_can_move`，`dist > moves_possible` 剪枝；考虑"今日能否移动"。
   - **乐观收益上界**：`cash + 0.5·p_w·W + 0.5·p_f·F + (T-t)·R`。
   - **Pareto 支配**：在 `(t, node, b)` 桶内按 (w, f, c) 三维剪枝（沿用 [pareto_prune_3d](#)）。
3. **Bellman 递推**：
   ```
   V(t, s, ω, b) = max_a min_{ω' ∈ W(b)} V(t+1, T(s,a,ω), ω', b - 1[ω'=X])
   V̄(t, s, ω, b) = max_a Σ_{ω' ∈ W(b)} P̂(ω,ω') · V̄(t+1, ...)
   ```
   字典序目标：先最大 V，再最大 V̄。
4. **条件化 Markov 权重**（修复关键 bug）：当 `future_storm_budget=0` 时归一化 `{S, H}` 上的权重；当 `>0` 时使用完整 `{S, H, X}` 权重。修复前错误地把完整矩阵权重用在 b=0 的归一化分母，违反"条件期望"的语义。
5. **`solve_initial_purchase_q4`**：枚举 `(water, food)` 组合（容量约束下），对每个候选评估第一日三个天气分支的鲁棒值，取使 `robust` 最大者。

**策略**：「起点超量采购 + 不挖矿 + 沿 BFS 最短路移动」——`safety_threshold` 与 `buffer` 两个超参控制起点超量规模。

- `SafeBaselinePlan`、`build_safe_baseline`、`simulate_safe_baseline`、`scan_safe_baselines`、`allowed_weather`、`budgeted_scenario_count`、`enumerate_budgeted_scenarios`、`_shortest_path`：全部原样保留。

## 四、第四关完整鲁棒 DP 关键算法说明

### 4.1 与第一问 DP 的一致点（手册 §6.4）

| 组件 | 第一问 dp.py | 第四关 AdaptiveBudgetRobustSolver |
|---|---|---|
| 状态结构 | 稀疏标签 `(t, node, w, f) → cash` | **同模式** + 多 2 维 `(c, b)` |
| Pareto 剪枝 | 2D frontier O(n²) | **同**（在 b 桶内 3D Pareto） |
| 时间下界 | 沙暴感知 BFS | **同**（加 future_budget 维度）|
| 收益上界 | `(cash + 0.5·p·W + 0.5·p·F + (T-t)·R)` | **同公式** |
| 村庄补给 | 完整枚举 `bw, bf` | **同**（村庄到达日补给） |
| 路径回溯 | `prev` 7 元组 | **扩展**为 9 元组（多 c, b） |

### 4.2 与第一问 DP 的关键差异

| 维度 | 第一问 dp.py | 第四关 AdaptiveBudgetRobustSolver |
|---|---|---|
| 信息结构 | 完全信息（已知完整天气） | **非前视 + 鲁棒**（仅知当天）|
| Bellman | `V(t+1, ..., 确定的下一日天气)` | `min_{ω' ∈ W(b)} V(t+1, ..., ω')` |
| 目标 | max Z | **max min** Z（最坏情况最大化）|
| Markov 权重 | 不需要（确定天气）| **条件化权重**（b=0 时归一化到 {S, H}）|
| 状态维度 | `(t, node, w, f)` | `(t, node, w, f, c, b)` 多 2 维 |

### 4.3 三处关键 bug 修复（实施过程中发现）

| Bug | 位置 | 现象 | 修复 |
|---|---|---|---|
| 时间下界不考虑"今日能否移动" | `_time_feasible` 旧版 | 沙暴日把可行状态误判为不可行 | 区分 `today_can_move` 与 `future_moves` |
| 沙暴预算传递错误 | 递归调用 day+1 | budget 符号含义混淆，路径不可达 | 区分 `storm_budget`（含今日）与 `future_storm_budget`（不含今日） |
| 沙暴预算=0 但当前是沙暴状态 | 进入非法状态 | NEG_INF 漂移 | 在 `_value` 入口加 `b=0 ∧ ω=沙暴 → NEG_INF` 一致性检查 |
| Markov 权重未归一化 | nominal 计算 | nominal 出现 < robust 的反常（违反数学） | 当 `future_storm_budget=0` 时归一化 `{S, H}` 上的 P̂ 行 |

**稳定区全为长度 1** —— 这表明安全下界**对 Γ 敏感**，每 +1 Γ 都需要不同的初购。论文中应**报告此现象**而非寻找"长稳定区"。
