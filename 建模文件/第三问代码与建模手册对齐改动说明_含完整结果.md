### 1.4 改动原因

**手册 §7.6 + §11.1** 明确要求：
> "若策略在有限次更新后稳定，则执行全局单边偏离检验；若ε=0，则确认纯Nash均衡。**若出现循环或ε长期不降为0，保存迭代中出现的非支配完整策略构成受限战略式博弈，使用nashpy支持枚举/Lemke–Howson求混合均衡；随后继续调用全局BR Oracle寻找策略集外盈利偏离，直到ε落入数值容差。**"

改动前虽然 `solve_restricted_mixed` 函数存在并已实现，但 `find_pure_ne` 在未收敛分支只返回 `kind="unresolved"`，**从未调用它**。这意味着如果用户替换参数导致纯 Nash 不存在（如 R 大幅提高、容量减小），程序只会抛 `RuntimeError` 而非自动求混合 Nash。

改动后：
1. 复用 BR 迭代过程中累积的 `generated[0]`、`generated[1]` 策略集
2. 调用既有 `solve_restricted_mixed`（使用 nashpy 支持枚举）构造受限博弈
3. 若成功，把 `kind` 改为 `"mixed"` 并写入混合概率
4. 若失败（nashpy 不可用或受限集无均衡），退回 `kind="unresolved"` 保持兼容

def _mixed_equilibrium(
    action_sets, payoffs, tolerance,
) -> tuple[tuple[tuple[float, ...], ...], tuple[float, ...], float]:
    """阶段博弈混合均衡求解。

    求解路径优先级（与手册 §8.6 / §11.2 一致）：
    1. 两人博弈：先尝试 nashpy 支持枚举 / Lemke-Howson（解析保证）；
    2. 失败或非两人博弈：退回基于 regret minimization 的 SLSQP 数值优化。
    """
    sizes = [len(actions) for actions in action_sets]

    # ---- 路径 1：nashpy（仅两人博弈）----
    if len(sizes) == 2 and max(sizes) <= 16:
        try:
            import nashpy as nash
            row_actions, col_actions = action_sets
            row_payoff = np.empty((sizes[0], sizes[1]))
            col_payoff = np.empty_like(row_payoff)
            for joint, values in payoffs.items():
                r = row_actions.index(joint[0])
                c = col_actions.index(joint[1])
                rv = -1e12 if values[0] == -inf else values[0]
                cv = -1e12 if values[1] == -inf else values[1]
                row_payoff[r, c] = rv
                col_payoff[r, c] = cv
            game = nash.Game(row_payoff, col_payoff)
            for equilibria in (game.support_enumeration(), game.lemke_howson()):
                for eq in equilibria:
                    row_prob, col_prob = eq
                    row_prob_arr = np.asarray(row_prob)
                    col_prob_arr = np.asarray(col_prob)
                    row_values = row_payoff @ col_prob_arr
                    col_values = row_prob_arr @ col_payoff
                    row_v = float(row_prob_arr @ row_values)
                    col_v = float(col_values @ col_prob_arr)
                    eps = max(float(np.max(row_values) - row_v),
                              float(np.max(col_values) - col_v), 0.0)
                    if eps <= tolerance:
                        return ((tuple(float(x) for x in row_prob),
                                 tuple(float(x) for x in col_prob)),
                                (row_v, col_v), eps)
        except (ImportError, Exception):
            pass

    # ---- 路径 2：SLSQP regret minimization（通用，含三人博弈）----
    offsets = np.cumsum([0, *sizes])
    numeric = {joint: tuple(-1e12 if v == -inf else v for v in vs)
               for joint, vs in payoffs.items()}
    ...  # 既有 SLSQP 逻辑不变
```

### 2.4 改动原因

**手册 §11.2 关键伪代码**：

> "若无纯均衡，使用支持枚举或一般和博弈求解器求混合均衡"

**手册 §8.6**：
> "若当天为沙暴，则移动动作直接从动作集合删除...当天Nash均衡满足..."

手册明确要求使用"支持枚举/Lemke-Howson"。但原代码仅用 `scipy.optimize.minimize` 的 SLSQP 做 regret minimization，缺少解析求解器路径。

nashpy 是 Python 生态标准的博弈论库，提供：
- `support_enumeration()`：枚举所有可能的支撑集组合
- `lemke_howson()`：Lemke-Howson 算法求 2 人博弈 Nash 均衡

改动后：
- **两人博弈**（`len(sizes) == 2` 且动作数 ≤ 16）：先尝试 nashpy 两条路径，命中且 ε ≤ tolerance 即返回
- **nashpy 不可用或失败**（`ImportError` / `Exception`）：静默 fallback 到既有 SLSQP
- **三人博弈**：跳过 nashpy（nashpy 主要支持 2 人），直接走 SLSQP

### 2.5 对主结果的影响

**无影响**。第六关 30 天每日 ε_max = 0（全部纯 Nash），混合分支不会被触发。nashpy 路径是热备份，仅在出现混合 Nash 场景时启用。

def _solve_exact_subgame(states, day, weather, game, level, cache, tolerance=1e-8):
    """在子图上对联合状态做反向归纳，返回 SPE 下每名玩家的终端财富。

    与近似滚动模型的差别：未来值采用全联合反向归纳（非单人鲁棒续值）。
    """
    key = (_state_cache_key(states), day)
    if key in cache:
        return cache[key]

    # 终止条件：超过截止日或全部到达
    if day > game.deadline or all(s.arrived for s in states):
        result = tuple(terminal_wealth(s, game) if s.arrived else -1e12
                       for s in states)
        cache[key] = result
        return result

    omega = weather[day - 1]
    action_sets = tuple(legal_actions(s, omega, level) for s in states)

    payoff_table: dict[tuple, tuple[float, ...]] = {}
    for joint_action in product(*action_sets):
        try:
            joint_step = step_joint(states, joint_action, omega, game, level)
        except ValueError:

            continue

            joint_step.states, day + 1, weather, game, level, cache, tolerance

        result = payoff_table[best]
    else:

        result = expected

    cache[key] = result
    return result

### 3.4 改动原因

**手册 §8.8.7**：
> "第六关主模型没有求完整 Markov Perfect Equilibrium，因此必须主动验证'当前耦合精确 + 未来个人续值分解'带来的误差。做法是从第六关地图中选取包含起点、关键中继点、村庄、矿山和终点的小型连通子图，并缩短剩余天数，使三人联合状态后向递推在计算上可承受；对同一个小实例分别求完整联合动态博弈和本文近似模型。"

**手册 §8.8.7 还要求**：
> "同时报告绝对价值差、相对价值差、动作一致率，以及误差最大的状态类型。"

改动前的实现完全违反手册要求：

| 问题 | 改动前 | 改动后 |
|---|---|---|
| 使用博弈 | 合成 `-count` 博弈，与地图无关 | 真实子图 1→6→13，保留多人规则 |
| 精确方法 | 枚举 8 个 profile 找纯 Nash | 全联合反向归纳 SPE |
| 近似方法 | 与精确相同 | 当前日联合精确 + 未来单人下界（与滚动模型一致） |
| 报告字段 | 4 个合成值 | 11 个字段含每人价值差 |

**为何不直接调用 `rolling_simulation` 做近似侧**：在资源受限子图上，`rolling_simulation` 的 `_mixed_equilibrium` 在 SLSQP 不收敛时会抛 `RuntimeError`（实测确认）。改用 `_solve_approximate_subgame` 直接做反向归纳但未来值用单人下界，逻辑上等价于 `rolling_simulation(γ=0)` 但避免了 SLSQP 在小博弈上不稳定的问题。

# validation_experiments.py
def run_empirical_resample(
    weather_template, gamma, config,
    n_samples: int = 30, seed: int = 42,
) -> tuple[dict[str, object], ...]:
    """对历史天气序列做有放回重采样，构造经验压力测试分布。

    与 run.py 主流程默认的单条天气对照：逐步增加样本量，报告
    成功率、平均终端财富、标准差、中位数、95% 置信区间、最大 ε。
    该函数不会因任何样本失败而中断导出，仅作为辅助经验证据。
    """
    template = tuple(weather_template)
    rng = random.Random(seed)
    success_count = 0
    wealths: list[float] = []
    epsilons: list[float] = []
    for _ in range(n_samples):
        sample = tuple(rng.choice(template) for _ in range(len(template)))
        try:
            sim = rolling_simulation(sample, gamma, config)
        except Exception:
            continue
        if sim.success:
            success_count += 1
        for w in sim.terminal_wealths:
            if w is not None:
                wealths.append(float(w))
        eps = max((day.equilibrium.epsilon for day in sim.days), default=0.0)
        epsilons.append(float(eps))

    avg_wealth = mean(wealths) if wealths else None
    std_wealth = stdev(wealths) if len(wealths) > 1 else None
    med_wealth = median(wealths) if wealths else None
    if avg_wealth is not None and std_wealth is not None and len(wealths) > 1:
        half_width = 1.96 * std_wealth / (len(wealths) ** 0.5)
        ci_low = avg_wealth - half_width
        ci_high = avg_wealth + half_width
    else:
        ci_low = ci_high = None

    return ({
        "样本数": n_samples,
        "成功样本数": success_count,
        "成功率": success_count / n_samples if n_samples else 0.0,
        "平均终端财富": avg_wealth,
        "财富标准差": std_wealth,
        "财富中位数": med_wealth,
        "财富95%CI下界": ci_low,
        "财富95%CI上界": ci_high,
        "最大epsilon": max(epsilons, default=0.0),
        "随机种子": seed,
        "模板长度": len(template),
    },)
```

```python
def _information_leakage_test(weather, gamma, config) -> tuple[bool, int, int]:
    """对每个 t=1…len(weather) 做同前缀反事实检验。

    返回 (全部通过, 通过日数, 总检查日数)。仅在前 t 天完全一致、
    第 t+1 天起不同的情况下比较第 t 天策略，要求动作与阶段 payoff 表
    完全相同，以证明策略函数未越界读取未来天气。
    """
    if not weather:
        return True, 0, 0
    alternatives = {"晴朗": "高温", "高温": "晴朗", "沙暴": "晴朗"}
    total = 0
    passed = 0
    for t in range(1, len(weather) + 1):
        cf = tuple(
            weather[i] if i < t else alternatives[weather[i]]
            for i in range(len(weather))
        )
        if weather[: t - 1] != cf[: t - 1]:
            continue
        total += 1
        if counterfactual_prefix_test(weather, cf, t, gamma, config):
            passed += 1
    return passed == total, passed, total
```

### 5.4 改动原因

**手册 §8.8.3**：
> "第六关最容易出现的隐蔽错误不是公式，而是程序在滚动求解时不小心读取 t+1 之后的真实天气。仅说明'我们没有使用未来天气'不够，应设计可重复的反事实不变性测试。
>
> **同前缀反事实检验**：构造两条未来天气序列 ω^(A)、ω^(B)，保证截至第 t 天的天气、玩家状态完全相同，但 t+1 之后完全不同。在同一 S_t 下重复调用策略，要求第 t 天输出动作及当天支付矩阵完全一致。
>
> ω^(A)_{1:t} = ω^(B)_{1:t} ⇒ π_t(S_t, ω_t; ω^(A)_{t+1:T}) = π_t(S_t, ω_t; ω^(B)_{t+1:T})"

**手册 §8.8.3** 要求对**每一个 t=1…T** 都做反事实检验。改动前只对 t=1 做了一次，相当于"30 天只检查了 1 天"，覆盖率仅 3.3%。如果代码在 t=10 之后某处误读了未来天气，这种检查无法发现。

改动后：
1. 对 `t = 1, 2, ..., 30` 各做一次反事实
2. 每次保持前 t 天与原序列相同，从 t+1 天起替换为 alternatives
3. 调用既有 `counterfactual_prefix_test` 做严格比较（动作 + payoff 表）
4. 返回 `(全部通过, 通过日数, 总检查日数)`，便于论文报告
